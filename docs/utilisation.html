1. Prérequis et installation

La chaîne d'outils est déclarée dans mise.toml : une commande l'installe, aux mêmes versions pour tout le monde. Deux prérequis restent manuels. 

# macOS (Homebrew) — les deux seuls outils à installer soi-même
brew install mise 1password-cli

# Récupérer et préparer le projet
git clone git@github.com:ECecillo/ebooks-translator.git epub-translator
cd epub-translator
mise trust                        # mise n'exécute pas la config d'un dépôt sans accord
mise install                      # go, java, just, golangci-lint, rg, python, uv
cp .env.example .env.local        # config NON SECRÈTE, gitignorée
just preflight                    # config + outils + session 1Password + santé NMT
go build -o ./bin/epub-translator ./cmd/epub-translator

Pourquoi mise plutôt qu'une liste dans un README

Le Justfile appelle dix outils ; l'ancien preflight en vérifiait cinq. python3, sqlite3, uv et docker n'étaient déclarés nulle part : ils échouaient en command not found au moment précis où vous lanciez just bible ou just compare. mise.toml rend la liste exécutable, et épingle notamment le Java ≥ 21 qu'epubcheck exige et qui n'existait que dans une phrase.

Piège de démarrage

GOROOT cassé (go: cannot find GOROOT directory) → préfixer les commandes : env -u GOROOT go test ./.... Ne jamais mettre ce préfixe dans une recette du Justfile.

Les secrets ne sont pas dans un fichier

Deux fichiers, deux rôles — c'est la règle à retenir :

FichierContenuVersionné ?
.env.localConfiguration non secrète : fournisseur, chemins de bases, plafonds, tarifs.non (gitignoré)
.env.opRéférences op:// vers le coffre 1Password. Aucune valeur.oui
# .env.op — committable tel quel, ce ne sont que des pointeurs
EPUB_TRANSLATOR_LLM_API_KEY=op://Dev/anthropic-epub-translator/credential
EPUB_TRANSLATOR_NMT_API_KEY=op://Dev/gcp-cloud-translation/credential

Les recettes qui appellent un fournisseur sont enveloppées dans op run --env-file=.env.op -- : la clé est résolue au lancement, vit dans la mémoire du processus le temps de la commande, et nulle part ailleurs. Les autres ne le sont pas — donc estimate, glossary-suggest et eval-ref ne demandent jamais de credential, puisqu'elles ne passent aucun appel.

Ce que la biométrie garantit, exactement

La demande Touch ID apparaît quand l'application 1Password est verrouillée. Tant qu'elle est déverrouillée, op autorise sans redemander. La garantie achetée est donc « le secret n'est jamais au repos sur le disque et ne fuit pas dans l'environnement », et non « un humain a approuvé ce run précis ». Pour la seconde, réglez le verrouillage automatique de l'app de façon agressive.

3.1 Google Cloud Translation — la clé API

  1. Console GCP → créer ou choisir un projet.
  2. Activer la facturation sur le projet. C'est obligatoire même pour le palier gratuit : sans elle, l'API refuse les appels alors que rien ne serait facturé.
  3. « APIs & Services » → « Enable APIs » → activer Cloud Translation API.
  4. « APIs & Services » → « Credentials » → « Create credentials » → API key.
  5. Restreindre la clé à la seule Cloud Translation API (« Restrict key » → API restrictions). Une clé non restreinte donne accès à tout ce qui est activé sur le projet.
Le palier gratuit, précisément

500 000 caractères par mois calendaire, partagés entre Basic et Advanced et pour tout le projet — environ un tome. Seul le dépassement est facturé. Le compteur du pipeline est son propre ledger de runs : si des caractères ont été consommés hors de cet outil ce mois-ci, la projection sous-estime d'autant. C'est NMT_FREE_CHARS_PER_MONTH qu'il faut alors baisser à la main.

3.3 Déposer les clés dans 1Password

Le projet attend des éléments de catégorie API Credential, dont le champ secret s'appelle credential — c'est ce que désignent les références op://<coffre>/<élément>/credential de .env.op. 

# 1. Activer l'intégration CLI ↔ app (c'est elle qui déclenche Touch ID) :
#    app 1Password → Réglages → Développeur → « Intégrer avec le CLI 1Password »

# 2. Trouver VOS coffres et VOS comptes — il n'y a pas de nom par défaut :
op account list        # les comptes connectés
op vault list          # les coffres du compte courant

# 3. Si plusieurs comptes sont connectés, épingler celui à utiliser dans .env.local
#    — cela vaut pour les recettes `just`, PAS pour ton terminal :
#      OP_ACCOUNT=my.1password.eu

# 4. Créer les éléments. --account est explicite ici : les commandes ci-dessous
#    tournent dans TON shell, qui ne source pas .env.local.
op item create --account my.1password.eu --category="API Credential" \
  --vault=Personal --title="anthropic-epub-translator" \
  credential="sk-ant-…"

op item create --account my.1password.eu --category="API Credential" \
  --vault=Personal --title="gcp-cloud-translation" \
  credential="AIza…"

# 5. Vérifier que chaque référence résout (c'est ce que fera `op run`) :
op read --account my.1password.eu "op://Personal/anthropic-epub-translator/credential"
op read --account my.1password.eu "op://Personal/gcp-cloud-translation/credential"
Deux pièges, dans cet ordre

1. Le coffre. Personal ci-dessus est un nom, pas un défaut : op item create --vault=X échoue avec "X" isn't a vault in this account si X n'existe pas chez vous. op vault list d'abord, puis adaptez .env.op — ne renommez pas vos coffres pour coller à une documentation.

2. Le compte. Une référence op:// nomme un coffre, jamais un compte. Avec un compte professionnel et un compte personnel connectés en même temps, op résout contre celui qu'il considère courant — d'où une clé perso cherchée dans le coffre de l'employeur. Le symptôme est trompeur : "Personal" isn't a vault in this account ressemble à un problème de coffre alors que c'est le compte qui est faux.

Et les deux réglages ne couvrent pas la même chose. OP_ACCOUNT dans .env.local tranche pour les recettes just, qui sourcent ce fichier ; votre terminal ne le source pas, donc les op item create et op read que vous tapez à la main ont besoin de --account (ou d'un export OP_ACCOUNT=… dans la session). just preflight vous avertit si plusieurs comptes sont connectés sans épinglage.

Dans l'app, clic droit sur le champ → « Copier la référence secrète » donne la chaîne op://… exacte, coffre compris.

Projet perso, compte perso

Si votre poste a les deux comptes, mettez les clés de ce projet dans le compte personnel. Une clé rangée dans un coffre géré par l'employeur relève de son administration et disparaît au départ ; ce n'est pas l'endroit d'un projet personnel.

4. Choisir et démarrer les services

Le pipeline a toujours besoin d'un moteur NMT : c'est le brouillon en mode nmt, et le repli en mode literary quand un lot LLM échoue.

ServiceCommandePortConséquence
NMT de devjust nmt-dev8081 Substitution mot à mot par dictionnaire. Préserve les placeholders. À ne pas utiliser pour juger la qualité — utile pour valider le pipeline gratuitement.
LibreTranslatejust libretranslate-up5050 Vrai NMT local. Le texte ne quitte pas la machine. Plus lent qu'un service hébergé.
Google Cloud Translationaucun service à lancer— L'adaptateur connaît l'hôte public : NMT_ENDPOINT peut rester vide. Les segments d'un chapitre partent groupés (≤ 128 textes ou 5000 caractères par requête) : le brouillon d'un tome passe de ~14 min à ~30 s. Le texte du livre est envoyé à Google.
COMET-QEjust comet-dev ou just comet-up8000 Notation sans référence. 1er lancement : ~2,3 Go de modèle. Sert à l'éval et à l'escalade sélective pendant un run.

5. Le parcours type

Traduire sérieusement une série, c'est cinq étapes dans cet ordre. Cliquez sur une étape pour voir la commande, ce qu'elle produit et ce qu'elle coûte.

Les étapes 1 à 3 se font une fois par série ; l'étape 4 se répète par tome.

6. Référence des sept commandes

run — traduire un livre

epub-translator run --input <f.epub> --output-dir <dir> --source-lang en --target-lang fr \
  [--mode nmt|literary] [--series <id>] [--glossary <f.json>] [--run-id <id>] \
  [--update-bible] [--resume] [--no-progress]
FlagDéfautEffet
--inputrequisL'EPUB source. Son nom de fichier (sans extension) devient le book_id.
--output-dirrequisLes artefacts vont dans <output-dir>/<run-id>/, pas directement dedans.
--source-lang / --target-langrequisV1 n'accepte que en → fr. Toute autre valeur est refusée à l'analyse des flags (exit 2), avant tout travail.
--modenmtnmt : brouillon + escalade optionnelle. literary : réécriture LLM de chaque segment frais, avec bible obligatoire.
--series—Obligatoire si --mode literary. Viser la bible bornée du tome : lumen@volume-01. Bible absente ou invalide = échec immédiat.
--glossary—Les termes locked sont masqués avant l'appel et resubstitués après. Une violation résiduelle fait échouer la porte QA.
--run-idhorodatage UTCNomme le dossier d'artefacts. Réutiliser le même identifiant écrase les artefacts précédents.
--update-biblefalseLaisse la bible évoluer pendant le run. déconseillé Casse le préfixe cacheable (≈ ×10 sur le coût) et rend les re-runs non reproductibles.
--no-progressfalseCoupe la barre de progression. Elle ne s'affiche de toute façon que si stderr est un terminal : redirigée ou en CI, il n'y a rien à couper. Le flag sert au cas que la détection ne couvre pas — une session capturée, un lecteur d'écran.
--resumefalseAujourd'hui un simple marqueur journalisé : la reprise vient de fait de la mémoire de traduction, qui resert tout ce qui a déjà été traduit. Relancer un run interrompu ne repaie pas le travail déjà fait.

Pendant le run, une ligne réécrite en place sur stderr dit où on en est. Elle n'existe que si stderr est un terminal, de sorte que just ci-local ou 2> run.log ne récoltent pas des retours chariot :

  • ch n'apparaît qu'en mode littéraire : le mode NMT aplatit le livre et ne suit pas les chapitres.
  • tm est la part des segments servis par la mémoire de traduction. C'est ce qui explique une barre qui avance vite puis ralentit : les hits sont instantanés, les appels fournisseur non.
  • Le montant est la dépense réelle cumulée, calculée par le même modèle de coût que actual_cost_usd dans report.json : le dernier chiffre affiché est celui que le rapport porte. Il n'apparaît pas quand il vaut 0 — un moteur auto-hébergé sans passe LLM ne coûte rien, et une colonne de $0.0000 serait du bruit. En mode littéraire il n'avance qu'aux coutures de chapitre : c'est là que le fournisseur rend les tokens qu'il a consommés.
  • L'ETA est retenue avant 10 % du livre — extrapoler la vitesse d'une rafale de hits TM annoncerait quelques secondes pour une heure de travail.
  • La dernière ligne, elle, part sur stdout : c'est la seule sortie analysable, et la barre ne s'y mélange jamais.

estimate — projeter le coût sans payer

epub-translator estimate --input <f.epub> [--escalation-rate 0.15]

Parse et segmente le livre, ne traduit rien, n'appelle aucune API, et imprime trois scénarios : NMT seul, hybride (la fraction --escalation-rate des segments passe au LLM), LLM complet.

Pourquoi cette commande est fiable

estimate et le garde-fou du run passent par le même modèle de coût, lisent le même compteur de palier gratuit dans le ledger et appliquent la même calibration. Ce que estimate annonce est ce que le plafond par livre applique. Corollaire : si les tarifs LLM ne sont pas renseignés dans .env.local, la projection vaut 0 $ et le plafond ne compare plus rien.

La calibration : ce que les runs passés ont mesuré

L'heuristique par caractères prédit la longueur d'une traduction ; elle ne prédit pas ce qu'un modèle dépense à la produire. Sur le chapitre 97 de vol33 elle projetait 16 180 tokens de sortie contre 53 409 consommés — 207 par segment au lieu de 63. Pas une marge, un facteur.

Le ledger (run_attempts) conserve donc les compteurs de tokens de chaque tentative, avec le couple (llm_provider, llm_model) qui les a produits. Le run suivant — et estimate — remplacent l'heuristique de sortie par cette mesure. La clé est le modèle et son transport, pas le livre : la verbosité d'un modèle se transporte d'un tome à l'autre, alors que rien dans les caractères d'un livre ne la prédit.

  • Une tentative morte avant sa passe LLM, ou dont le transport ne rapporte aucun usage, ne calibre rien : la moyenne ne compte que les tentatives qui ont des segments et des tokens. Sinon la projection deviendrait moins chère à chaque run planté.
  • La moyenne est pondérée par les segments : un tome de 4 000 segments en dit plus sur un modèle qu'un test de 20, et faire la moyenne des deux ratios leur donnerait le même poids.
  • Ledger absent = rien de mesuré. estimate n'en crée pas un : c'est une commande sèche, elle ne laisse pas une base de données derrière elle.
Deux corrections qui font monter les chiffres — volontairement
  • Le transport CLI est facturé comme s'il réécrivait son préfixe à chaque appel. Avec LLM_CHAT_PROVIDER=claude-cli, chaque invocation est une session neuve : rien ne garantit qu'un préfixe survive pour être relu. C'est un majorant, pas une description — voir les deux mesures ci-dessous. Sans lui, la projection était de ×1,9 à ×3,7 trop basse sur ces mêmes runs, toujours dans le sens qui laisse un plafond budgétaire passer un run. Un plafond qui surestime refuse du travail qu'il pouvait s'offrir ; un plafond qui sous-estime ne borne rien.
  • La passe d'escalade ne bénéficie d'aucun cache. Le post-éditeur HTTP est un POST JSON vers un endpoint quelconque, sans cache_control : son préfixe est payé plein tarif à chaque appel — ce que le commentaire du code affirmait déjà (« paid once per segment ») pendant que l'arithmétique facturait une écriture puis N relectures bon marché. La ligne hybrid monte donc franchement. C'est un majorant, et la conclusion qu'il porte est celle que le projet répète : l'escalade est chère au mot.

Ce que deux runs du même chapitre ont mesuré

Même chapitre (97 de vol33, 258 segments, 6 lots), même modèle (claude-sonnet-5 via claude-cli), même bible v3, à deux semaines d'écart :

Runécriture de cachepar appellecture de cacheentrée totalesortie / segmentcoût notionnel
ch97-sonnet · 08/08281 81946 970191 000472 8332071,9153 $
ch97-cli · 23/0883 56013 927201 885285 4571600,9950 $

Le premier ressemble exactement à six réécritures complètes du préfixe. Dans le second, les lectures dominent : le cache par contenu du fournisseur se déclenche visiblement de lui-même, ce que le montage posait comme sa question ouverte. Même transport, un facteur 3,4 d'écart sur le terme même que le majorant facture.

D'où la conclusion à retenir : sur ce transport, la projection borne une dépense, elle ne la prédit pas. Sur le run du 23/08 elle annonçait 1,1373 $ pour 0,9950 $ réels (+14 %) ; sur celui du 08/08 le même modèle aurait annoncé 1,1373 $ pour 1,9153 $ (−41 %). L'erreur change de signe — c'est le signe qu'on tient une borne, pas une loi. L'ancien modèle, lui, se trompait toujours dans le même sens.

series-bible — construire la bible avant de traduire

epub-translator series-bible --input-dir ./books/lumen --series lumen [--samples 3] [--merge] [--dry-run]
FlagDéfautEffet
--input-dirrequisTous les .epub du dossier, en ordre de publication déduit du nom de fichier.
--samples3Documents échantillonnés par tome pour le style, les voix et le vouvoiement. Attention : ils partent tous dans un seul appel, donc l'entrée croît avec la série — voir l'encadré ci-dessous.
--mergefalseEnrichit les bibles existantes au lieu de les écraser.
--dry-runfalseImprime la projection de coût et s'arrête avant le premier appel. Rien n'est créé — pas même la base de la bible.

La projection de coût

estimate chiffre la traduction d'un livre ; il ne sait pas chiffrer un build de bible, qui est une autre forme de travail. series-bible porte donc sa propre projection, imprimée systématiquement avant le premier appel, et le plafond par livre s'y applique. 

epub-translator series-bible --input-dir ./epub/lumen --series lumen --samples 3 --dry-run

Le piège de --samples

--samples ressemble à un réglage par tome, mais la passe de style concatène tous les échantillons dans un seul appel. Sur 33 tomes, --samples 8 envoie 966 526 tokens en une requête — au-delà de la fenêtre de contexte de Haiku 4.5 (200 K), et absurde partout ailleurs. La commande vous avertit au-dessus de 200 000 tokens. --samples 3 tient en 9 703 tokens.

Sans tarifs LLM renseignés

La projection imprime quand même les tokens — c'est le cas du montage claude-cli, où il n'y a pas de dollar marginal et où le token est le seul chiffre qui compte. Elle le dit explicitement plutôt que d'afficher 0,0000 $ en silence, et aucun plafond ne s'applique alors.

Sortie : une bible par tome (lumen@volume-01, lumen@volume-02, …) plus lumen = la bible du tome le plus récent. Les synopsis d'une bible sont bornés aux tomes 1..N pour ne pas divulguer la fin d'une histoire qu'on commence. Coût : environ 1 + (chapitres + 1) appels LLM par tome, une fois, jamais rejoué.

Conséquence à connaître

Regénérer la bible change le préfixe des prompts, donc invalide le cache LLM une fois. C'est voulu : un coût ponctuel par regénération, au lieu d'un coût par chapitre. Les tomes déjà traduits ne sont pas re-traduits automatiquement.

style-profile — amorcer la bible depuis un seul tome

epub-translator style-profile --input <f.epub> --series <id> [--samples 3] [--merge]

Un seul appel LLM, un seul tome, pas de synopsis. Utile pour un livre isolé ou pour corriger le style d'une bible existante avec --merge. series-bible le supplante pour le travail en série.

glossary-suggest — extraire les noms propres

epub-translator glossary-suggest --input <f.epub> [--out glossary.json] [--min-count 3]

Gratuit, heuristique, aucune configuration requise — c'est la seule commande qui ne charge pas la config. Elle produit un squelette JSON à curer à la main : garder les vrais noms, écrire la forme française, retirer le bruit, cocher locked. Monter --min-count réduit le bruit et laisse passer des noms rares. 

[
  { "term_en": "Elena", "term_fr": "Elena", "locked": true },
  { "term_en": "Return by Ash", "term_fr": "Retour par la Cendre", "locked": true }
]

eval — mesurer la qualité

# chrF : nécessite une référence humaine de la MÊME édition
epub-translator eval --candidate ./runs/<id>/translated.epub --reference ./ref-fr.epub

# COMET-QE : sans référence, nécessite un service COMET actif
EPUB_TRANSLATOR_COMET_ENDPOINT=http://localhost:8000/score \
  epub-translator eval --segments ./runs/<id>/segments.jsonl
Choisir la bonne métrique

Comparer une traduction de light novel à une référence web novel donne un chrF catastrophique qui ne dit rien de la qualité : ce ne sont pas les mêmes textes. Sans référence alignée, COMET-QE est la métrique honnête. La moyenne par livre atterrit dans report.json (avg_quality_score) et metrics.json.

batch — traiter un dossier de livres

epub-translator batch --input-dir ./books/serie --output-dir ./runs \
  [--glossary ./glossary.json] [--reference-dir ./refs] [--no-progress]
  • Mode NMT uniquement — pas de mode littéraire en batch.
  • Une TM et un glossaire partagés entre les livres : le tome 2 réutilise les phrases du tome 1, et la terminologie reste cohérente d'un bout à l'autre.
  • Un livre en échec n'arrête pas les suivants ; le premier échec fixe le code de sortie.
  • Les artefacts vont dans <output-dir>/<book-id>/, plus un batch-report.json agrégé.
  • --reference-dir : si <dir>/<book-id>.epub existe, un chrF est calculé pour ce livre et injecté dans le rapport agrégé. Sans référence pour un livre donné, on passe en silence.
  • Chaque livre a sa propre barre de progression, préfixée de son book_id et refermée par la ligne de récapitulatif du livre. --no-progress les coupe toutes.
  • Ctrl-C arrête proprement entre deux livres.

8. Les variables qui changent le rendu

Les flags décident quoi traduire ; l'environnement décide comment. Voici celles dont l'effet est visible dans le fichier produit ou dans la facture.

Variable (EPUB_TRANSLATOR_)DéfautConséquence si vous y touchez
NMT_PROVIDERhttp Change la qualité du brouillon, donc la qualité finale en mode nmt et le travail restant au LLM en littéraire. Change aussi le tag engine écrit en TM.
LLM_MODEL + tarifs— Change la qualité littéraire et le coût. Sans les tarifs, la projection vaut 0 $ et le plafond par livre ne protège plus rien.
LLM_TOKEN_MULTIPLIER1.0 Corrige la densité du tokenizer (1.30 pour claude-sonnet-5 et la famille Opus 4.7). Sans lui, la projection sous-estime d'autant et le garde-fou laisse passer un run trop cher.
LLM_CHAT_PROVIDER=claude-cliopenai expérimental Passe par le CLI Claude Code local au lieu de l'API : plus de clé, facturé sur le siège d'abonnement. Voir la section dédiée ci-dessous.
LLM_CLI_BINvide → claude Exécutable des fournisseurs CLI. À renseigner si le binaire n'est pas dans le PATH ou pour épingler une version.
LLM_BATCH_SIZE0 → 50 Segments par appel. Plus haut = moins d'appels, donc moins de répétitions du préfixe ; mais un modèle qui n'arrive pas au bout déclenche des réessais en demi-lots. Baisser pour un petit modèle local, monter pour un gros modèle.
LLM_ESCALATE_MIN_CHARS240 Mode nmt uniquement : seuil de longueur au-delà duquel un segment part au post-éditeur. 0 escalade tout. Fait varier directement le nombre d'appels LLM.
COMET_ENDPOINT + ESCALATE_BELOW_SCOREvide / 0 Bascule l'escalade de « par longueur » à « par qualité » : seuls les brouillons notés sous le seuil partent au LLM. Ajoute la métrique translation_quality_score.
PER_BOOK_ / DAILY_ / MONTHLY_BUDGET_USD2 / 5 / 50 Plafonds durs vérifiés avant le premier appel payant → exit 7. Le défaut de 2 $ refuse volontairement un tome littéraire sur modèle Sonnet (~4–6,50 $).
NMT_FREE_CHARS_PER_MONTH0 (500 000 auto pour Google) Seul le dépassement est facturé. Le compteur est le ledger de runs : si des caractères ont été consommés hors pipeline ce mois-ci, la projection sous-estime.
TM_PATH./tm.sqlite Changer de fichier = repartir sans mémoire : tout est retraduit et repayé. Un fichier partagé entre tomes est ce qui fait monter le taux de réutilisation.
LLM_CACHE_PATH./llm_cache.sqlite Le supprimer rend un re-run payant. Le garder rend un re-run identique gratuit et instantané.
EPUBCHECK_JAR / EPUBCHECK_BINvide Non renseigné = validation EPUB ignorée (et non échouée) : la porte QA passe sur les seuls contrôles statiques. Le rapport le dit via epubcheck_skipped.
RUN_TIMEOUT_SECONDS0 Borne un livre. Utile en batch pour qu'un fournisseur bloqué ne fige pas la série. Le dépassement donne exit 8, et la dépense déjà engagée est quand même enregistrée.
NMT_MAX_ATTEMPTS / NMT_RETRY_BASE_MS3 / 200 Réessais sur erreur transitoire, en backoff. Attention : chaque tentative consomme des caractères chez le fournisseur, et le compteur le reflète.
LOG_LEVELinfo debug détaille le routage segment par segment dans logs.ndjson. Les payloads ne sont jamais journalisés.

8.1 Le montage expérimental : Claude Code CLI au lieu de l'API

LLM_CHAT_PROVIDER=claude-cli remplace l'appel HTTP par un sous-processus claude -p --output-format json, authentifié par la session de l'application. Aucune clé API, donc aucune enveloppe op run : le Justfile le détecte et lance directement. LLM_MODEL accepte alors un alias du CLI (opus, sonnet, haiku) ou un nom de modèle complet. 

EPUB_TRANSLATOR_LLM_CHAT_PROVIDER=claude-cli
EPUB_TRANSLATOR_LLM_MODEL=opus
EPUB_TRANSLATOR_LLM_CLI_BIN=                  # vide = "claude" depuis le PATH
# Les tarifs restent renseignés : ils ne facturent rien ici, ils font du
# plafond par livre un indicateur de quota consommé.
EPUB_TRANSLATOR_LLM_INPUT_PER_MTOK_USD=15.00
EPUB_TRANSLATOR_LLM_OUTPUT_PER_MTOK_USD=75.00
La mesure qui rend le montage viable

L'adaptateur passe --system-prompt, qui remplace le prompt système de l'agent, et --tools "", qui coupe l'outillage. Sans ces deux options, chaque invocation traîne le préambule complet de Claude Code. Mesuré le 8 août 2026, sur un prompt d'une ligne :

InvocationTokens d'entrée mis en cacheÉquivalent API
claude -p nu48 8700,2936 $
avec --system-prompt + --tools ""2 0270,0126 $

24× de surcharge en moins par appel, et un tome en fait plus de soixante-huit.

Ce que ce montage vous fait perdre
  • Le garde-fou budgétaire cesse de décrire une dépense réelle. Un abonnement n'a pas de coût marginal. Garder les tarifs publiés du modèle transforme le plafond par livre en indicateur de quota — c'est le meilleur substitut que le pipeline sache calculer, mais ce n'est plus une facture.
  • Le cache_control vous échappe. L'adaptateur Anthropic marque explicitement le préfixe stable ; ici c'est le CLI qui décide. Le préfixe reste identique octet pour octet entre les lots d'un chapitre, donc le cache par contenu du fournisseur peut se déclencher seul. llm_cache_read_tokens dans report.json est le nombre qui le dit — le premier à regarder après un vrai run.
  • Pas de sortie structurée native. Le CLI n'a pas d'équivalent au schéma JSON de l'API : le schéma devient une instruction. Le décodeur tolérant et le rattrapage en demi-lots absorbent la différence, au prix de quelques lots dégradés de plus.
  • MaxTokens est ignoré (le CLI n'expose pas le réglage) : c'est la limite du modèle qui s'applique.

Avant de lancer un tome, la vérification de bout en bout — elle consomme du quota, donc elle est explicitement optionnelle : 

EPUB_TRANSLATOR_LIVE_CLI_TEST=1 EPUB_TRANSLATOR_LLM_MODEL=opus \
  go test ./tests/integration/ -run TestLiterary_ClaudeCLI -v
# → traduit 3 segments, vérifie les placeholders, et affiche les compteurs :
#   usage: input=2 output=164 cache_read=0 cache_creation=2847

9. Lire les artefacts d'un run

runs/20260808-142312/
├── translated.epub   ← le livre
├── report.json       ← segments, hits TM, tokens, coûts, bloc QA
├── segments.jsonl    ← 1 ligne par segment (entrée de eval --segments)
├── metrics.json      ← métriques à plat, noms canoniques
└── logs.ndjson       ← logs structurés
Les artefacts sont écrits même si la QA échoue

Un run qui sort en exit 5 a quand même produit son EPUB et ses rapports : c'est ce qui permet de diagnostiquer. Regardez d'abord, dans report.json, le bloc qa : placeholder_restore_ratio (seuil 0,995), untranslated_segments, missing_spine_docs, glossary_violations, epubcheck_passed.

Les champs de report.json qui servent à la calibration

ChampCe qu'il dit
llm_pass_segmentsCombien de segments la passe LLM a portés, résultat exploitable ou non — à distinguer de llm_segments, qui compte ceux qu'elle a améliorés. C'est le dénominateur qui va avec les compteurs de tokens : diviser les tokens d'un lot dégradé par les segments qu'il n'a pas livrés rendrait un modèle d'autant plus « verbeux » qu'il se comporte mal.
llm_provider / llm_modelQui a consommé ces tokens. C'est la clé sous laquelle la mesure est réutilisable. Renseignés en mode littéraire seulement : le post-éditeur HTTP est choisi par endpoint, pas par modèle, et ne rapporte aucun usage à attribuer.
llm_cache_creation_tokensLe préfixe écrit dans le cache. Sur claude-cli, en le divisant par le nombre d'appels on voit s'il est réécrit à chaque fois — c'est le premier chiffre à regarder pour comprendre une facture.

Les statuts d'un segment dans segments.jsonl

StatutSignifie
reusedServi par la mémoire de traduction. Zéro appel, zéro coût.
translatedBrouillon NMT. En mode littéraire, c'est le signe que le LLM n'a pas pu le raffiner (lot dégradé) — cherchez le warning correspondant dans logs.ndjson.
post_editedRéécrit par le LLM, placeholders vérifiés. C'est le statut nominal en mode littéraire.

Relecture humaine, côte à côte

just compare runs/<id>/segments.jsonl relecture.html   # tableau EN | FR dans le navigateur

Ce que le compose ne couvre pas, par conception

Le mode littéraire fonctionne via app (il lit .env.local, donc la clé API), mais le LLM est une API externe, pas un service hébergé : pour l'activer en conteneur il faut adapter la command: du service app (--mode literary --series … --glossary …).
